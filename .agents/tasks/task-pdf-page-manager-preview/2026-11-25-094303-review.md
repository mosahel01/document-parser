## High-level view

The fix aligns the lightbox Delete handler with the other four deletion paths: `const newCount = book.slots.length - 1` followed by the same conditional flag set. All deletion sites now share the same `newCount > 0 && newCount <= 20` condition.

The one remaining asymmetry: `deleteSelected` and the per-card × call `setPreview(null)` before setting the flag, so the stale preview disappears immediately while the rebuild runs. The lightbox Delete skips `setPreview(null)`. On a ≤20-page document auto-preview fires and replaces whatever was there, so the user sees no stale state. On a >20-page document the old preview stays up until manually refreshed.

### Stale preview on >20-page documents after lightbox delete

`deleteSelected` and the per-card × both call `setPreview(null)` immediately, so the old preview card disappears while the new one builds (confirmed). The lightbox Delete does not:

```tsx
onClick={() => {
  const newCount = book.slots.length - 1
  setBook(...)
  setSelected(...)
  if (newCount > 0 && newCount <= 20) autoPreviewPending.current = true
  setLightboxId(null)
  // setPreview(null) is absent
}}
```

On a ≤20-page document, auto-preview fires and replaces the preview before the user notices. On a >20-page document, the preview remains showing the pre-deletion page count and content. Clicking Preview manually gives a correct result, so no data is wrong — but the stale card is visually misleading. Adding `setPreview(null)` before `setLightboxId(null)` closes the gap.

</details>
