## High-level view

Both v1 blocking issues are resolved. "Browse all tools" is now `md:inline-flex` (not `sm`), eliminating the crowding. `App.tsx` passes `categories={navCategories}` and `onSelectTool={select}` to `AppFooter` at line 745.

The privacy banner is rendered in a `<>` fragment above `<header className="sticky top-0">`. Because only the `<header>` is sticky, the banner scrolls off with the page body on the first scroll event. It disappears permanently rather than waiting for the user's × click.

Both "Start for free" and "Browse all tools" call `onGoHome`, which routes to `select('home')`. They navigate identically and are both no-ops when the home page is already active.

`NavigationMenu` opens on `onMouseEnter` and closes on `onMouseLeave` at the wrapper `div` level. A click also toggles `openCategoryId`. Clicking to open and then drifting the pointer off the wrapper column closes the menu before the user can select an item — hover-only users are unaffected, but click or keyboard flows are broken.

The `<header>` then correctly sticks, but the banner is gone. Wrap both in a sticky outer element (e.g. `<div className="sticky top-0 z-40">`) or move the banner inside the header.

A distinct behaviour, or removing the redundant button, is needed.

Clicking to open and moving the pointer off the wrapper closes the menu. Decide on one open mechanism: hover-only (remove the click toggle) or click-only (remove the leave handler).

## Privacy banner scrolls away

`AppHeader` returns a `<>` fragment. The banner `div` is the first child; the `<header>` is the second. Only `<header>` carries `sticky top-0 z-40`. The banner is in normal document flow, so it scrolls off on the first scroll event. The user dismisses it with ×, but if they scroll before reading it, it disappears without any interaction.

The fix is straightforward: wrap the fragment's root in a sticky container that holds both the banner and the header bar, or give the banner its own `sticky top-0` and give the `<header>` `top-[banner-height]`. Moving the banner inside `<header>` and conditionally adding padding is simpler but changes the header's height when the banner is visible, which the `h-16` constraint would need to accommodate.

## Duplicate CTA buttons

```
// AppHeader.tsx lines 100–113
<button onClick={onGoHome} className="... sm:inline-flex">Start for free</button>
<button onClick={onGoHome} className="... md:inline-flex">Browse all tools</button>
```

`onGoHome` maps to `() => select('home')` in App.tsx. On the home page both buttons do nothing visible. The reference design's two navbar buttons ("Login", "Sign up free") have distinct destinations; the two here should as well. The simplest fix: make "Browse all tools" scroll to `document.getElementById('tools')` or call `onSelectTool` with a home-and-filter combination.

## NavigationMenu hover/click conflict

Each category wrapper `div` has `onMouseEnter={() => setOpenCategoryId(cat.id)}` and `onMouseLeave={() => setOpenCategoryId(null)}`. The trigger button also has `onClick={() => setOpenCategoryId(isOpen ? null : cat.id)}`. A click opens the menu; moving the pointer off the wrapper then closes it via `onMouseLeave`. Hover navigation is unaffected, but a click-primary or touch-emulation flow cannot reliably reach a menu item. The two mechanisms need to be reconciled: either remove the click toggle and go hover-only, or remove the leave handler and go click-only.
