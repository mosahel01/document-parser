# MergePDF brand restyle and component redesign

The diff rebases the product from "Document Toolkit" to "MergePDF" and brings its visual language close to the `generated.html` reference. The colour palette shifts from purple to red (`#e2173a`), the font changes from Ubuntu to Inter, and every surface, card, and tool header is adjusted to match the reference's spacing and radius values. Five targeted FEAT-001 items (ToolCard radius/padding, filter-tab sizing, AppHeader buttons, Brand wordmark colour, hamburger animation) are confirmed delivered. The scope is wider than FEAT-001 alone: FileDrop, ToolHeader, NavigationMenu, AppFooter, GlobalSearch, ThemeToggle, the CSS token set, `index.html` meta, and roughly a dozen tool-panel components are also restyled.

**Watch for:**
- The AppHeader renders two full-width `sm:inline-flex` buttons ("Start for free" + "Browse all tools") side by side at the `sm` breakpoint; on a 640–900 px viewport they crowd the search button and ThemeToggle out. *(confirmed)*
- `AppFooter` now requires `categories` and `onSelectTool` props, but its call site is not in this diff. If `App.tsx` was not updated the footer will fail to compile. *(possible — no App.tsx diff present)*
- The localStorage key changed from `document-toolkit-theme` to `mergepdf-theme`, so returning users will lose their saved theme preference on first load. *(confirmed)*

**Verdict**: NEEDS_CHANGES

## High-level view

The colour token swap (purple → red) and font swap (Ubuntu → Inter) are global: every component that uses a CSS token or `font-sans` inherits the change without being touched. The added tokens `accent-soft`, `pink`, `shadow-sm/md/lg` tighten the reference match and are used throughout.

The FEAT-001 items all land correctly. `ToolCard` has the right radius (`rounded-[10px]`) and padding (`pt-7 px-5 pb-6`). The filter tabs carry the reference's exact padding and font size. The "Showing X tools" row is gone. The AppHeader exposes "Start for free" and "Browse all tools". The hamburger animates into an X. The `BrandWordmark` now reads Merge in `text-accent` for both branches (the non-inverse branch changed from `text-brand` to `text-accent`; because `--brand` and `--accent` now share the same value this produces no visual difference, but the semantic alignment is correct).

The `AppFooter` is a full rewrite: a dark multi-column layout with real link columns derived from the `categories` prop. This is a prop-contract change. The footer now requires two new props, but `App.tsx` is not in the diff, making it unclear whether the call site was updated.

The AppHeader's two action buttons are both `hidden sm:inline-flex`, which puts them both on screen from 640 px up. At that width the header row also carries a search button and a theme toggle. The four items compete for space and the two buttons have no max-width guard, so they can push each other and the icons off-screen on a 640–768 px viewport.

The `localStorage` key rename is a silent reset for any existing user. There is no migration, which is expected for a pre-launch product, but it is worth noting if any test users have saved preferences.

## AppHeader button layout at sm breakpoint

The right end of the header row now contains four elements at `sm` and above: a search button, `ThemeToggle`, the red "Start for free" button, and the outline "Browse all tools" button. The last two are both `hidden sm:inline-flex`. On a 640 px viewport (the exact `sm` breakpoint), the navigation logo, the search button, the toggle, and two text buttons must all fit in one row. Neither button has a character limit or `whitespace-nowrap` concern, but their combined width (~220–240 px at `text-sm font-semibold px-4 py-2`) plus the search button and toggle leaves almost no room for the logo on small phones in landscape or on a narrow window. The reference (`generated.html`) shows only "Login" and "Sign up free" with the burger hiding at a narrower breakpoint — it never shows four right-aligned items at once.

The fix is to gate "Browse all tools" at `md` rather than `sm`, which matches the reference's intent and keeps the header usable on 640–768 px viewports.

## AppFooter prop contract

The old `AppFooter` took no props. The new one takes `{ categories: NavCategory[], onSelectTool: (id: string) => void }` and derives four column sets by filtering `categories` by id (`'pdf'`, `'documents'`, `'images'`, `'archive'`). `App.tsx` does not appear in the diff, so the call-site update cannot be confirmed here — it should be checked explicitly.

## localStorage key rename

`ThemeToggle` reads and writes `'mergepdf-theme'`; `index.html`'s inline script now reads `'mergepdf-theme'` too. Any stored preference under `'document-toolkit-theme'` is silently dropped on first load after the update.
